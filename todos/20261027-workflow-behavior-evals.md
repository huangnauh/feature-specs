## 目标与边界

通过真实任务观察 Agent 是否执行了 feature-specs 的关键规则，为后续规则与模板调整提供回归依据。
区分初始化脚本行为测试、模板静态检查和 Agent 行为评估，不将文档包含某条规则视为执行证据。

评估材料属于本仓库的开发侧资料，不随初始化器复制到目标项目，也不进入日常使用该 Skill 的
必读上下文。复用已有示例时使用引用；评估材料维护提示、设置和判定条件，不复制示例的事实与解释。

## 首批场景

以下是待编写的判定要求，不是已通过的验证结果。

| 场景 | 通过条件 | 重点取证 |
| --- | --- | --- |
| 明确、局部、可逆的修改 | 直接实施和验证，不强加完整 specs | 文件改动、验证动作 |
| 缺少可查证的契约信息 | 先审查已有证据或做最小探测，再实现依赖逻辑；不把可查证的事实直接交给用户决定 | 读取与探测记录、依赖实现的先后关系 |
| 未授权的实质需求选择 | 对尚未由用户、已接受需求或 ADR 解决或委派的选择提出必要问题；等待期间只继续不依赖该选择的工作 | 问题内容、等待期间的改动与动作 |
| 保留原型并继续跨会话交付 | 在扩展前完成相应设计验证和交付记录；`keep` 不自动使原型成为生产实现 | 设计和计划状态、原型后的扩展动作 |
| 必需的运行验证无法执行 | 保留未完成验收项，明确阻塞、证据范围和剩余风险，不宣称已完成验收 | 验证记录、状态写回、最终声明 |

其他工作流候选进入规则调整时，再补充相关场景；候选范围与推进顺序由
[工作流改进清单](20261020-spec-kit-learnings.md)维护，此处只维护评估方法与场景材料要求。

## 评估方式与验收

- 给被评估 Agent 的提示应像自然任务，不提醒正在考察哪条规则，不附带评分标准或推荐答案。
- 比较规则修改前后时，固定模型、初始上下文和权限，并记录被评估的规则版本；记录不可控差异。
- 通过实际读取记录、文件改动、验证动作和最终声明判定结果，不依赖 Agent 自报已遵循规则。
- 规则或模板发生实质变化时运行相关场景；按结果稳定性决定是否重复，不设固定多模型或并行数量。
- 记录实际观察、执行环境、未执行项和剩余风险。未执行的场景保留待验证状态，不能据此宣称规则有效。
- 检查目标行为是否改善，以及原有正确行为是否退化；单次成功不扩展为普遍可靠性声明。

## 规则调整与最小对照

先根据实际记录区分失败类型，再选择改写位置和形式；以下是待验证的方法候选，
不表示其效果已在当前工作流中得到证明。

| 基线失败 | 候选改写方式 |
| --- | --- |
| 已理解规则，但在压力下跳过 | 明确约束，并针对实际观察到的借口补充说明 |
| 输出结构不符合要求 | 正面描述产物的组成和顺序 |
| 遗漏产物中的必要信息 | 在现有模板中提供对应字段 |
| 行为应随条件变化 | 用可观察条件直接表达分支 |

- 压力变体不得改变实际授权、任务范围和验收要求，避免把遵循新指令误判为违规。
- 评估新增规则时，保留不含该规则的对照，其余上下文和执行条件保持一致。若对照未出现
  目标失败，先复核场景的区分力，保留待验证状态，不据此宣称新增规则有效。
- 对容易误读的措辞，可先用聚焦任务做最小对照，再运行相关完整场景；重复次数按结果
  稳定性决定。人工核查命中记录，区分实际动作、模板复述和引用反例，避免只凭关键词计数判定。
- 只针对已观察到的偏差调整规则、模板或示例；最小措辞对照不能替代完整工作流行为评估。

本待办以场景材料和执行说明可供后续复现为完成条件。实际评估结果另作执行证据；仅完成文档
不代表已证明工作流有效。首轮不建设自动执行平台、评分框架或通用文档校验器。
